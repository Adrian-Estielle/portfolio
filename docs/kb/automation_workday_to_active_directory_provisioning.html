WORKDAY · ACTIVE DIRECTORY · HYBRID IDENTITY

Workday → Active Directory inbound provisioning.

Hybrid provisioning pattern using the Entra provisioning service and an on-premises provisioning agent, with directory-health preflight, OU scoping, identity matching, pilot testing, portal logs, and agent-side troubleshooting.

PRE-FLIGHT

Prove the directory is healthy before introducing an automated writer.

Replication

repadmin /replsummary
repadmin /showrepl *

Confirm that object changes can converge across the DCs that will answer users, applications and administrators.

Domain-controller health

dcdiag /e /c /v

Use broader diagnostics where replication failures may be tied to DNS, services or DC health.

Target OU

  • Create a dedicated pilot OU.
  • Delegate only the rights needed to create/update target user objects.
  • Do not begin with a production-wide OU target.

Naming & matching

  • Define sAMAccountName collision behavior.
  • Define UPN-generation rules.
  • Choose a durable worker identifier for source-to-target matching.

WORKDAY SOURCE

Use the same source-security discipline as cloud-only provisioning.

  1. Create an Integration System User (ISU) for provisioning.
  2. Create or assign the appropriate Integration System Security Group.
  3. Grant the domains required by the mapped worker attributes.
  4. Activate pending Workday security-policy changes.

If the integration identity cannot read a source attribute, downstream mapping changes will not create the missing data.

ENTRA PROVISIONING APPLICATION

Create the Workday-to-AD application and register the on-premises agent.

Enterprise application

  1. Microsoft Entra admin center → Enterprise applications → New application.
  2. Select the Workday-to-Active-Directory user-provisioning gallery application.
  3. Open Provisioning and set the mode to Automatic.

Provisioning agent

  1. Use a stable, domain-joined Windows Server intended for infrastructure workloads.
  2. Install the Microsoft provisioning agent from the application's setup flow.
  3. Register the agent to the tenant through the supported wizard.
  4. Verify that the agent reports healthy before continuing.
Treat the agent host like production infrastructure: patching, DNS, time, service health and network reachability matter.

CONNECTION & TARGET

Make the source, forest and target container explicit.

Provisioning configuration typically needs:

  • Workday WWS endpoint and ISU credentials.
  • Active Directory forest/domain details.
  • Target container / OU distinguished name.
  • Agent assignment / connectivity.
Example sanitized target
OU=PilotUsers,OU=Provisioned,DC=corp,DC=example,DC=com

Run the supported connection test before mapping or pilot execution.

MAPPINGS & PILOT

Prove one worker through the entire path before broadening scope.

Review mappings

  1. Open the worker-to-AD user mapping.
  2. Confirm the stable matching attribute.
  3. Confirm sAMAccountName / UPN generation and collisions.
  4. Confirm the target OU and required AD attributes.

Provision on demand

  1. Choose one representative pilot worker.
  2. Run Provision on demand.
  3. Verify the user exists in the intended pilot OU.
  4. Verify mapped attributes and access-assignment prerequisites.
  5. Confirm the object is visible consistently where multiple DCs are involved.

Only after the pilot path is correct should continuous provisioning be enabled for the intended population.

TROUBLESHOOTING

Use portal logs and agent state together.

Portal

Enterprise application → Provisioning logs. Start with the evaluated action, status, failure reason and correlation details for the worker/object.

Agent-side traces

A common trace location for the provisioning agent is:

%ProgramData%\Microsoft\Azure AD Connect Provisioning Agent\Trace

Exact paths/product naming can change with agent versions, so verify against the installed version when troubleshooting.

“Success” but object is inconsistent

Check agent permissions/connectivity, then AD replication. A user present on one DC and absent on another is a directory-health problem, not proof of random provisioning behavior.

Common causes

  • OU delegation insufficient for the requested operation.
  • AD replication unhealthy.
  • DNS/time problems on the agent or DCs.
  • Match-key or naming collisions.
  • Source Workday permissions omit mapped attributes.
