INFRASTRUCTURE OWNERSHIP

Learning the whole environment, then improving the parts that create friction and risk.

A sanitized summary of the approach I used while growing from support/escalation work into broader systems and cloud ownership in a Microsoft-centered enterprise environment.

CONTEXT

An environment that had grown across multiple layers.

Scale

Roughly 1,200 users and more than 2,000 managed endpoints across Windows, macOS, Microsoft 365, on-premises Active Directory, Entra ID, SaaS applications, Azure resources and legacy server workloads.

Operating reality

Support issues rarely stopped at one product boundary. Endpoint state, identity, Conditional Access, VPN/network paths, licensing, file services and backend server dependencies frequently intersected.

APPROACH

Map dependencies first; automate after the process is understood.

Identity

Administered AD / Entra lifecycle work, SSO/MFA, group and license assignment, and progressed manual onboarding/offboarding toward HR-driven provisioning with PowerShell and Workday integration.

Endpoint

Managed Intune and Jamf across 2,000+ endpoints, including Autopilot, compliance baselines, BitLocker, Conditional Access, application deployment, configuration profiles and remediation scripts.

Cloud & servers

Migrated legacy Windows workloads into Azure, built validation environments, modernized storage and remote access patterns, and administered backup and monitoring for critical resources.

Operations

Used PowerShell and lightweight tooling to reduce repetitive administration, while documenting procedures so service desk and systems work could be executed consistently.

REPRESENTATIVE CHANGES

Examples of the infrastructure work that followed.

Identity lifecycle

Built and refined account lifecycle automation, culminating in Workday-to-Entra / Active Directory provisioning patterns with attribute mappings and role/group assignment logic.

Provisioning runbook

Endpoint standardization

Used Intune/Autopilot and Jamf to move endpoint configuration toward policy-driven enrollment, encryption, compliance, application deployment and remediation rather than one-off fixes.

Endpoint runbooks

Azure operations

Migrated selected Windows application workloads from on-premises infrastructure to Azure with test environments and staged validation; deployed Azure Backup for 150+ resources and Azure Monitor alerting for key VMs/applications.

Storage & collaboration

Reworked an accounting-data migration after testing exposed limitations in the initial design, separating collaborative working data, SMB-oriented storage and archival tiers instead of forcing every workload into one platform.

Read storage migration case study

WHAT THIS DEMONSTRATES

The value was the cross-system ownership.

The useful part of this experience was not simply having access to a long list of consoles. It was learning how identity, endpoint state, cloud services, legacy servers, network paths, backup, monitoring and support processes affected one another—and then changing the environment in ways that reduced recurring operational work.
